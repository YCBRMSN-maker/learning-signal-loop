# learning-signal-loop

校园教学场景的 **Agent Skill**：用**一条学情信号闭环**，同时支撑「学生端 · 个性化答疑」与「教师端 · 学情智能研判」。

纯文本方法论，**不含可执行代码**。安装后由 agent 依据其中的判据、参数与坑清单去实现。

---

## 解决什么

两类校园教学痛点，彼此耦合：

| 角色 | 痛点 |
| --- | --- |
| **学生** | 自主学习缺少针对性支撑；卡壳时无人察觉；练习反馈不具体 |
| **教师** | 学情数据分散、难以判断真实学情；班级水平差异大、难以分层教学 |

## 为什么把两者放在一起

它们不是两个独立功能，而是**同一套学情信号的两端消费**：

```
学生答题
  → 行为采集
  → 沙箱预检：逐条检查点判定对错
  → BKT 吸收对错信号，更新知识点掌握度
  → 情绪识别判断是否挫败
  → 状态聚类更新学习档位（Normal / Advanced / Struggling）
  → 下次提问时：RAG 召回知识 + 掌握度 + 情绪 + 聚类档位
  → 一起注入提示词 → 大模型输出个性化回复
```

**判题产生信号 → BKT 与聚类吸收信号 → 情绪提供当下状态 → RAG 提供知识 → 组装进提示词 → 大模型输出。**

学生端拿这批信号调讲解深度与介入时机；教师端拿同一批信号做研判与分层。这正是破解「AI 落地碎片化、场景单一、融合度低」的关键 —— 不为每个痛点各造一套技术栈。

## 五个支撑技术

| 技术 | 一句话 |
| --- | --- |
| **情绪识别** | 对单条消息分类（积极 / 中性 / 消极），输出标签与置信度；失败时自动降级 |
| **学习状态聚类** | 离线训练聚类中心，在线算距离归三档，带进度分与置信度 |
| **BKT 知识追踪** | 用贝叶斯更新为每个知识点维护掌握概率，由答题对错驱动 |
| **RAG 知识增强** | 文档切分 → 向量化 → 近似最近邻召回 → 注入提示词 |
| **行为采集与解释** | 上报空闲、失败、编辑等事件，跨消息累积权重，配合时间窗口判定 |

另有 **沙箱预检**（闭环的信号源头，基础设施）与 **多服务容器化部署**（工程侧）。

## 能回答什么问题

适合在这些时候调用：

- 学生端的**主动提示**怎么设计才能不打扰学生？
- **情绪识别**没有标注数据，怎么冷启动？
- 掌握度为什么不更新？**RAG** 召回为什么不准？
- 怎么判断班级里谁该**分层**？依据是什么？
- 这条链路的**建设顺序**是什么，哪一步不能颠倒？
- 功能上线前该**验收**哪些点？

## 适用边界

- 判据（三分类边界、BKT 参数、聚类离线训练 + 在线距离）是通用的
- 种子语料采自**编程教学（HTML/CSS/JS）场景**；换到数学、英语等学科，判据仍可用，种子样本需重新采集
- 不含代码，**不会自动产出功能** —— 由 agent 依据其中的判据与参数去实现
