# 系统分层与调用链路

这份文档讲**这类系统该怎么分层、一次交互要走哪些环节**。它是通用设计建议，**不含任何文件路径**——具体落到哪个文件由你自己的工程决定。

## 分层建议

| 层 | 职责 | 边界 |
| --- | --- | --- |
| 接口层 | 路由定义 | 薄层：只做入参校验与响应封装，不写业务逻辑 |
| 服务层 | 业务逻辑 | 所有 AI 能力都在这一层 |
| 数据访问层 | 数据读写 | 唯一允许写 ORM 查询的地方 |
| 模型层 | 表结构定义 | — |
| 契约层 | 请求 / 响应 DTO | 含统一响应结构，成功与失败共用一个壳 |
| 配置与装配层 | 配置与依赖注入 | 环境变量、常量、服务实例注册 |
| 异步任务层 | 后台任务 | 慢操作与集中写库 |
| 静态数据层 | 知识库、索引、判题用例、学习内容 | 构建期 / 离线产物 |

三条硬边界：

1. **接口层不写业务** —— 业务下沉到服务层，便于复用与测试。
2. **数据访问只在数据访问层** —— 禁止在服务层散落裸 SQL。
3. **服务装配集中在一处** —— 新增服务必须在那里注册，否则注入不到。

## 一次学生交互的完整链路

这是理解全局的主线，改动任何一环都建议顺着它走一遍：

```
聊天模块（订阅「开始 / 流式分片 / 结束」渲染流式回复）
  → 统一 HTTP 入口（自动附带参与者标识）
  → 问答接口（校验请求）
      ├─ 同步入口：直接调编排器
      └─ 异步入口：请求入问答队列，用任务 ID 轮询结果
  → 编排器（核心）
       ├─ 读学生状态载体（含知识掌握度）
       ├─ 情绪识别
       ├─ 学习状态聚类归类
       ├─ RAG 召回相关知识点
       ├─ 加载学习内容
       ├─ 行为计数与解释
       ├─ 组装 system prompt 与 messages
       └─ 调用大模型
  → 异步落库，记录交互与行为
  → 统一响应结构返回前端
```

一句话：**编排器把「学生状态 + 知识片段 + 行为 + 历史」拼成提示词，再交给大模型。**

## 各环节的职责

### LLM 网关

统一的模型调用出口。集中管理三组**彼此独立**的配置（对话、Embedding、翻译），各自一套 key / 模型名 / base url。负责客户端初始化、对话调用、拼接 system prompt 与 messages、提取回复并记录 token 用量。

翻译单独一个网关：中文提问对英文知识库召回效果差，中间加一层翻译能显著提升召回率。

### 学生状态载体

学生画像结构，承载知识掌握度、情感状态、行为模式、代码行为分析、进度聚类字段。

**这是学习路径与状态推荐的数据核心** —— 所有信号最终汇聚到它身上，所有消费方都从它读。先有这个载体，再谈学情视图。

### 情绪识别

本地 BERT 系模型对文本分类，输出 `NEGATIVE / NEUTRAL / POSITIVE` 与置信度。模型缺失或加载失败时**自动降级**，不阻断问答链路。

消费方：提示词组装（语气调节）、挫败检测（连续答错 + 负向情绪）。

### 学习状态聚类

- 特征工程：句向量编码 → 窗口池化 → 降维 → 归一化
- 在线推理：与离线聚类中心算余弦距离取最近类，返回 `cluster_id / cluster_name / progress_score / confidence`
- 类别语义：`Normal / Advanced / Struggling`，直接映射教学档位
- 设计要点：**离线训练中心、在线只算距离**，不在请求链路里跑聚类算法

### 行为分析

行为事件分发表，把前端上报的事件（测试提交、AI 求助、知识点访问、代码行为、空闲等）映射到不同处理逻辑。行为上报入口**异步落库并异步解释**。

关键路径：**测试提交 → 触发掌握度更新，并同步更新情绪状态与挫败检测。** 这条链路断了，整条信号闭环就断了。

### RAG 检索

- 构建：读取源文档 → 切分 → 向量化 → 建索引。两个产物必须**一起持久化**：向量索引 + 分片文本
- 检索：查询文本转向量（可先做中文翻译）→ 近似最近邻召回 top-k → 返回命中分片
- 切分参数：`chunk_size=500`、`chunk_overlap=50`
- **改知识库后必须重建索引**，否则召回永远是旧内容

### 提示词组装

定义 AI 教师 system prompt，并按「学生状态 + RAG 上下文 + 对话历史 + 代码 / 测试结果」拼装完整 prompt。复杂拼接处要写清「为什么这样喂」的注释。

### 知识追踪

由答题对错更新知识点掌握概率，四参数可配置（见 `technologies.md`）。**更新时机是判题结果回写时，不是聊天时。** 消费方：学习路径推荐与知识点排序。

### 沙箱预检

入口语义：`run_evaluation(user_code, checkpoints, topic_id)`。实现：无头浏览器加载学生页面，支持 raw HTML 与标准模板两种模式，注入 CSS/JS 后**逐条执行检查点**并收集失败反馈。

闭环节点：判题结果要回写掌握度与情绪状态，不能只返回结果就结束。

### 异步队列

按任务性质拆队列：问答、行为处理、提交评测、集中写库。队列名集中定义，任务路由在一处声明，避免散落。

## 需要持久化的静态产物

| 产物 | 内容 |
| --- | --- |
| 向量索引 + 分片文本 | RAG 检索用，必须成对出现 |
| 知识图谱 | 知识点依赖关系 |
| 学习内容 | 按主题组织的内容结构 |
| 判题用例 | 检查点与测试任务 |
| RAG 源文档 | 索引的原始输入 |

这些产物要么是构建期生成、要么是离线训练得到，**不要在每次请求里现算**。
