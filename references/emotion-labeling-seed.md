# 情绪识别的冷启动：用真实教学语料做标注种子

情绪识别最难的不是模型，是**第一份标注数据**。这份文档给出一套在编程教学场景里可直接复用的判据与种子样本。

## 为什么不能靠通用语料

可下载的中文情绪语料都是**广泛领域的日常表达**，与校园教学场景的语言分布不同——学生做题时说的话，和日常表达不是一套句式。

教学场景的情绪信号高度依赖三类**特有句式**：

| 句式类型 | 标记词 | 教学场景示例 |
| --- | --- | --- |
| 重复失败标记 | 「还是」「又」「第八个」 | 「还是不对啊」 |
| 结果质疑标记 | 「明明」「是不是你们判断有错」 | 「明明是正确的」 |
| 自我否定标记 | 「我不懂」「我不清楚」「我不是很理解」 | 「我还是不懂」「为什么这没通过」 |

这三类句式在日常语料里几乎不出现，通用模型抓不到。**判据与种子样本必须来自教学场景本身。**

## 三分类判据

不看有没有问号，看**是否表达了自我否定或对结果的不满**。

| 信号 | 积极 | 中性 | 消极 |
| --- | --- | --- | --- |
| 核心特征 | 明确表达收获或感谢 | 单纯的未知概念、信息缺口 | 重复失败 / 质疑结果 / 自我否定 |
| 关键词 | 「太…了」「谢谢」「有趣」「讲得很仔细」 | 「X 是什么」「有什么区别」「怎么做」「有没有语法」 | 「还是」「又」「明明」「不懂」「不清楚」「没通过」 |
| 人称 | 常含正向评价 | 无「我 + 否定」 | 常含「我 + 否定」或「为什么我…」 |

## 原始意图 → 三分类映射

从真实日志里可以分出五类原始意图，映射关系如下：

| 原始意图 | 示例 | 映射标签 | 理由 |
| --- | --- | --- | --- |
| A 挫败 / 对结果不满 | 「还是不对啊」 | **消极** | 重复失败 + 对结果不满，最强信号 |
| B 求答案 / 求提示 | 「能不能给我答案」 | **中性** | 单纯的求助行为，情绪本身中性 |
| C 正向 / 礼貌 | 「太谢谢了，你讲得很仔细」 | **积极** | 带程度副词或具体夸赞的真实正向 |
| E 概念困惑 | 「我还是不懂」 | **消极** | 含第一人称否定，是负面自我认知 |
| F 知识提问 | 「ol 和 ul 有什么区别」 | **中性** | 主动求知，无情绪指向 |

注意 **E 与 F 必须分开**：两者表面都是"提问"，但「我还是不懂」有第一人称否定，「ol 和 ul 有什么区别」没有。若按"出现不会的概念 = 消极"来标，会把**学习动机最强的学生标成情绪最差**。

## 种子样本

### 消极

```
我错哪里了
还是不对啊
你看我错哪里来
为什么我的测试没通过啊？
我想知道为什么没通过
我现在哪里有问题，你可以告诉我答案吗
还是不能
我代码错哪了
我哪里有错？明明是正确的啊。我不理解，为什么这没通过！！！是不是你们的判断有错
哪里出了问题呢？我明明写了
你帮我看看哪里有问题
我还是不懂
我不清楚
我不是很理解复选框和单选框
```

最后一条（含「！！！」「是不是你们判断有错」）是本类最强样本：**挫败 + 质疑系统 + 情绪强度**三层叠加。

### 中性

```
ol 和 ul 有什么区别
h 和 p 有什么区别
Flex 布局怎么设置子元素横向排列、居中显示、支持自动换行
html 块级元素有哪些
我需要语法，不是答案
这题怎么写
文本的提示属性是什么
无序列表是什么
```

「我需要语法，不是答案」虽中性，但体现了明确的学习动机，是识别"依赖答案型学生"的关键对照样本。

### 积极

```
用复选框！太谢谢了，你讲得很有趣很仔细
我还不熟悉这个流程，不过谢谢你
```

**积极样本最稀缺**——真实语料里只有极少两条明确正向表达。寒暄类（「你好」「嗨」「哈吉米」）不带情绪指向，应标**中性**，不要因为"看起来友好"就标积极。

## 三条最容易标错的边界

**1. 「X 是什么」是中性，不是消极**
区分点：有没有「我 + 否定」。「我不懂」→ 消极；「X 是什么」→ 中性。

**2. 「还是不对」是消极，不是中性**
「还是」「又」标记了**重复失败**，是挫败的核心词。这是整批语料里最可靠的消极信号。

**3. 「太谢谢了」是积极，「谢谢」是中性**
礼貌用语本身不算情绪。**带程度副词或具体夸赞**（「太」「讲得很仔细」）才是真实正向。

## 怎么用

这批语料**量级不足以训练模型**，只能当种子：

1. **few-shot 种子**：每类挑 3–5 条挂进提示词，要求模型输出结构化结果：

```json
{"sentiment": "positive | neutral | negative", "confidence": 0.0-1.0}
```

2. **人工验收集**：留出 20 条做人工盲标，比对模型输出与人工标签的一致率。一致率是这套能力**唯一能对外汇报的指标**。

3. **规则兜底**：把「还是」「明明」「我不懂」做成关键词兜底层，模型不可用时仍能触发干预。

## 内部四分类、对外三分类

三分类能满足汇报口径，但会**丢掉关键区分**：

| 状态 | 表现 | 该给的干预 |
| --- | --- | --- |
| 困惑 CONFUSED | 「我还是不懂」「X 是什么」 | 换讲法、降难度、补前置知识 |
| 挫败 FRUSTRATED | 「还是不对」「为什么没通过」 | 先安抚情绪、再定位错误 |

「不懂」要**换讲法**，「不对」要**先安抚**——干预方式完全不同。建议：

- **内部保留四类**：`NEUTRAL / CONFUSED / FRUSTRATED / POSITIVE`，用于驱动干预策略
- **对外合并三类**：`CONFUSED + FRUSTRATED → 消极`，用于汇报与统计

这样既不丢干预能力，又能对上三分类口径。

## 常见坑

- **把系统注入的内容当学生输入**。对话日志里的"用户消息"常被拼进题目描述、代码片段、判题结果、选中的元素上下文，这些不是学生打的字，必须先剔除再标注。
- **只标单条消息**。挫败往往由「连续失败 + 负面表达」共同定义，单看一句话会把「还是不对啊」标成中性。
- **用公开数据集直接微调**。场景语言分布不匹配，训出来的模型在教学场景里的表现会明显低于跑分。
- **标注后不做一致性校验**。没有人工盲标比对，就无法证明标签可信。
