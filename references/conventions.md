# 工程规范与常见坑

来源：团队代码规范、Git 协作约定，以及实际开发中反复出现的问题。写代码前过一遍这份清单能省下大量返工。

## 接口与异常

- 成功统一返回一个**标准响应结构**（数据装在固定字段里）；业务失败抛带状态码与说明的异常。
- 禁止吞异常：`except Exception: pass` 一律不允许；捕获具体异常类型，向上抛时携带上下文。
- 禁止吞掉异常后返回 `None` 让上层猜。
- 外部调用（LLM、Redis、沙箱）必须做超时与降级，失败要有日志。

## 日志

- 统一使用标准 `logging`，关键路径必须打点：请求入口、任务入队、判题结果、AI 调用成功/失败。
- 禁止在日志中打印密钥、token、用户密码。
- 错误日志要带足够上下文：接口、参数、异常堆栈。

## 分层与数据访问

- 数据访问统一走 `crud/` + SQLAlchemy ORM，禁止散落裸 SQL。
- 表结构变更必须提供迁移或初始化脚本，保证可重建。
- 多个服务（API / Worker）共享同一数据库，禁止各写各的。

## 配置与常量

- 禁止魔法值散落：与业务含义绑定的常量集中到**统一配置层**或模块顶部。
- 前端常量放模块顶部常量区，同一类消息类型集中在一处声明。
- 常量命名必须表达业务含义，禁止 `A/B/C` 式命名。

## 代码格式与注释

- Python：PEP 8，4 空格缩进，行长 ≤ 120。
- JavaScript：2 空格缩进，语句以分号结尾。
- 注释统一用中文；公共函数/类必须有 docstring，说明功能、参数、返回值。
- 复杂逻辑（BKT 模型、RAG 流程、iframe 选择器）必须写清「为什么这样做」，而不是复述代码在做什么。
- 删除无用的 import、未使用变量、死代码。

## 前端

- 所有 HTTP 请求统一走一个**封装的 API 客户端模块**，禁止页面内散落 fetch/axios。
- 使用 ES Modules，模块职责单一：通用能力放一个目录，页面级逻辑放另一个目录（一页一文件）。
- 跨域 iframe 通信统一用 `postMessage`，并且必须校验来源。
- DOM 查询集中管理，避免 `getElementById` 散落各处。
- 第三方库本地化托管，禁止外网 CDN（国内访问不稳定、演示会翻车）。
- 新增页面必须与现有页面目录结构一致，并接入导航。

## 依赖与构建

- 部署用的依赖清单必须**锁版本**（Docker 构建用它），开发用的依赖清单与之保持同步。
- 新增依赖需团队确认并说明用途，禁止顺手加一堆没用的包。
- 生产依赖与开发工具依赖尽量分离。
- 下载镜像统一走国内源（清华 PyPI / 阿里），npm 用 npmmirror，保证构建稳定。

## Git 协作

- `main` 为受保护分支，禁止直接 push，所有变更走 PR。
- 分支统一 `feature/` 前缀，例如 `feature/trend-fix`；功能完成即合并删除。
- 禁止 `--force push` 到 `main` 或他人分支；不直接改动他人的 feature 分支，先沟通再走 PR。
- Commit 格式 `<type>: <subject>`，type 取 `feat` / `fix` / `docs` / `refactor` / `test` / `chore` / `style`，例如 `fix: 修复测试结果一直加载中的问题`。
- 提交前自检：`.gitignore` 生效、无垃圾文件、无敏感信息、无调试残留。

## 安全

- 密钥、token、数据库密码一律放 `.env` / 环境变量，禁止入库。
- 用户输入必须校验，防止注入与异常数据破坏流程。
- 代码评测必须在沙箱执行，禁止在宿主机直接运行用户代码。
- 接口错误信息对用户友好，内部细节只进日志。
- 前端展示不要泄露内部路径、密钥等敏感信息。

## 不入库清单

`*.db`（运行时数据库）、`*.bak`、`*.tmp`、`__pycache__/`、`node_modules/`、虚拟环境、模型权重、误产生的杂散文件。

## 常见坑

| 症状 | 原因与处理 |
| --- | --- |
| 改了 Worker 相关代码但行为没变 | 异步任务的改动必须同步到所有 worker 进程并重启，API 进程改动不影响 worker |
| 掌握度不更新 | 先确认判题结果是否真的回写；BKT 只在判题结果回写时更新 |
| RAG 召回还是旧内容 | 改完知识库没有重建向量索引 |
| 模型反复重试直到死循环 | 契约校验报错太笼统，必须点名具体缺的键名 |
| 跨 Session 取值报惰性加载错误 | 跨 `with SessionLocal()` 块传值前，先在会话内取出标量 |
| 任务写进去了但接口读不到 | 多服务没有共享同一数据库卷 |
| 前端改了没生效 | 静态资源要设 `no-cache`，否则浏览器一直吃旧缓存 |
| 依赖安装慢或构建失败 | 换国内镜像源；构建缓存异常时清理后重新构建 |
| 页面加载极慢 | 引了外网 CDN，改成本地托管 |

## PR 提交前检查清单

- [ ] 功能自测通过（本地跑通主要流程）
- [ ] 代码符合命名、格式、注释规范
- [ ] 无垃圾文件混入
- [ ] 无敏感信息泄漏
- [ ] 无调试残留（`console.log`、`print` 堆栈）
- [ ] 依赖变更已在部署与开发两份依赖清单中同步
- [ ] 涉及数据库变更已提供初始化/迁移说明
- [ ] PRD / TDD 等相关文档已同步更新
